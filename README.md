# kb-qa —— 个人知识库问答助手

把你的 PDF 丢进去，用自然语言提问，它从你的文档里找出相关段落，
用大模型组织成答案，**并标注每句话出自哪一段**。

> 这是我为求职准备的第一个完整项目。目标不是"功能多"，
> 而是**每一行代码我都能讲清楚为什么这么写**。

---

## 它解决什么问题

大模型不知道你的私人文档。你有一本 200 页的教材、一份公司内部手册、
一堆技术文档，直接问它，它要么不知道，要么一本正经地编（**幻觉**）。

RAG（检索增强生成）的思路是：

```
    不要指望模型"记住"你的知识，
    而是在它回答之前，先把相关的那几页递给它。
```

**事实交给文档，表达交给模型。** 这是当前企业落地 AI 最主流的方案之一。

---

## 技术选型与理由

| 选择 | 理由 |
|---|---|
| **DeepSeek API** | 便宜、国内直连、兼容 OpenAI 协议（换模型只改一个环境变量） |
| **requests 手写 HTTP** | 不套 SDK，能亲眼看清楚"调用大模型"到底发了什么 JSON |
| **不用 LangChain** | 抽象层会把原理藏起来。先手写一遍，才知道框架帮你做了什么 |
| **PyMuPDF** | 中文 PDF 提取最快、乱码最少 |
| **关键词检索（TF-IDF）** | 零依赖、毫秒级、结果可解释，作为第 4 阶段的对比基线 |
| **不用向量数据库** | 安装易踩坑、收益不明显。第 4 阶段用 numpy 手写余弦相似度 |

## 项目结构

```
kb-qa/
├── src/
│   ├── step1_extract.py     # ① PDF → 纯文本
│   ├── step2_chunk.py       # ② 长文本 → 小块（含重叠）
│   ├── step3_retrieve.py    # ③ 关键词检索：找出最相关的 K 块  ← 核心
│   ├── step4_answer.py      # ④ 拼 Prompt → DeepSeek → 带引用的答案
│   └── make_test_pdf.py     # 生成测试用 PDF
├── data/
│   ├── pdf/                 # 放你的 PDF（已 gitignore）
│   ├── extracted.txt        # 中间产物：提取的纯文本
│   └── chunks.json          # 中间产物：切好的块
├── .env                     # 你的密钥（已 gitignore，绝不提交）
├── .env.example
└── requirements.txt
```

## 快速开始

### 1. 装依赖

```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

> ⚠️ 必须加 `-i https://mirrors.aliyun.com/pypi/simple/`，否则国内直连会超时。

### 2. 配置密钥

```bash
cp .env.example .env
```

用记事本打开 `.env`，把 `API_KEY` 换成你自己的（[DeepSeek 开放平台](https://platform.deepseek.com/) 申请，充 10 块钱够用很久）。

### 3. 放入你的 PDF

```bash
# 生成一份测试文档（可选）
./.venv/Scripts/python.exe src/make_test_pdf.py

# 或把你自己的 PDF 放进 data/pdf/ 目录
```

### 4. 跑整条链路

```bash
PDF="data/pdf/算法学习笔记.pdf"

./.venv/Scripts/python.exe src/step1_extract.py "$PDF"   # 提取
./.venv/Scripts/python.exe src/step2_chunk.py            # 切块
./.venv/Scripts/python.exe src/step3_retrieve.py "快速排序的时间复杂度"  # 检索
./.venv/Scripts/python.exe src/step4_answer.py "快速排序的平均时间复杂度是多少？"  # 问答
```

`step3` 和 `step4` 不带参数运行会进入**交互模式**，可以连续提问。

## 实测效果（测试文档：5 个块）

**提问：** 快速排序的平均时间复杂度是多少？最坏情况呢？

```
快速排序的平均时间复杂度是 O(n log n) [1]，最坏情况下的时间复杂度是 O(n²) [1]。

最坏情况出现在每次选取的基准值都是当前序列中的最大值或最小值时，
这会导致每次分区只能减少一个元素 [1]。

【出处】
  [1] 块 #0 (相关度 40.13)
```

**提问文档里没有的内容：** Python 的 GIL 是什么

```
抱歉，我在知识库中没有找到与这个问题相关的内容。
```

→ 没有编造，符合预期。

## 已知短板（第 4 阶段要解决）

我特意测了关键词检索的边界，**它确实有短板，这是我要用向量检索去改进的动机**：

| 提问 | 检索得分 | 结果 |
|---|---:|---|
| 「折半查找的平均查找长度」 | 27.65 | ✅ 命中正确块 |
| 「怎么解决**哈希表存满**的问题」 | 7.74 | ❌ 文档里写的是「装填因子」「冲突」，字面不重叠就匹配不到 |

**根因：** 关键词检索数的是"字面重叠"，理解不了同义表达。
「存满」和「装填因子」是同一个意思，但没有一个字相同。

**这个短板不是 bug，是我做对比实验的素材**——
第 4 阶段接上向量检索后，同一个问题再测一次，
就能拿到"关键词 vs 向量"的真实数据对比。**这是简历上最有价值的一段。**
